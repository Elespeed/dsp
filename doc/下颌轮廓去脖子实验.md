# 下颌轮廓去脖子实验

## 范围

实验分支 `codex/jaw-contour-evaluation` 从 v5 提交 `f37d17a` 创建。使用 `fig/最新测试.mp4` 已入选的 43 帧，以及 v4/v5 已保存的原图、肤色 mask 和候选线。原视频不纳入 Git。本轮仅生成离线预览，`FaceLocator` 仍调用 v5 的 `RunNeckRefined`，不改变摄像头插件。

实际用于比较的是二值 mask，而不只是画框图。用户在第 001 帧截图中用绿线标出真实下巴位置，明显高于先前实验所画的黄色曲线。此前把衣领边缘当成下巴、认为 v2 在前两帧“保留了下巴”的解释是错误的。v5 也不能直接当作正确分割的真值。

## 方法

`tools/jaw_contour_probe.py` 以 v4 黄色候选线记录的脸部横向范围和下巴初值为起点，在原图灰度上比较候选线两侧亮度。它从 `RunRefined` 的 mask 重新裁剪，以便在必要时恢复 v5 曾裁掉的下巴。由于依赖 v4 的候选线图片，这只是离线原型，不是可直接接入插件的实现。

| 迭代 | 搜索约束 | 结果目录 |
| --- | --- | --- |
| v1 | 每一列独立寻找较暗的下方边缘，并用连续性约束连接 | `fig/iterations/latest-video-jaw-contour-v1/` |
| v2 | 只允许一条平滑、单峰的抛物下颌弧线 | `fig/iterations/latest-video-jaw-contour-v2/` |
| v3 | 使用面部关键点构成脸部外轮廓，与现有肤色 mask 求交 | `fig/iterations/latest-video-jaw-landmark-v3/` |

两个目录中的 `candidate/` 是原图上的黄色候选线，`mask-jaw/` 是实验 mask，`comparison/` 左侧为 v5 mask 叠加图、右侧为本轮 mask 和候选线，`contact_*.png` 是总览，`results.csv` 记录逐帧像素数与边缘分数。
`results.csv` 的像素数按 160×120 二值 mask 计数；旧版分割 CSV 按课程接口坐标尺度将其乘以 2，因此两种表格的数值不能直接比较。

## 逐帧观察

- v1 在第 001、002 帧和多张后续帧沿衬衫领口走出锯齿或 W 形，说明单凭最强灰度边缘容易把衣领误认为下颌。
- v2 避免了 W 形，但第 001 帧黄色曲线仍落在真实下巴以下的衣领附近；第 005、013、026 帧也有类似现象。面积增加不能说明下巴保留得更完整。
- v4 未产生候选线的 9 帧在两轮中直接保留 v5 结果；例如第 035 帧未得到新的下颌轮廓。

v2 的 43 帧中，25 帧比 v5 像素更少、7 帧更多、11 帧相同。这些数字只描述 mask 面积变化，不代表准确率或颈部去除率。当前没有逐像素人工真值，且上述可见错误已足以表明 v1/v2 不能通过“保留下巴且稳定去脖子”的验收。

## v3：按真实下巴位置修正的离线参照

`tools/jaw_landmark_probe.py` 使用 [MediaPipe Face Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/python) 的面部关键点，并按[官方面部外轮廓连接关系](https://ai.google.dev/edge/api/mediapipe/python/mp/tasks/vision/FaceLandmarksConnections)得到脸部外轮廓。它将外轮廓与当前版肤色 mask 相交，避免将脖子保留在 mask 中；如果未检测到脸或下巴关键点落在当前框外，就保留 v5 结果。绿色是外轮廓，黄色点是下巴尖端，与 v1/v2 的黄色领口曲线含义不同。

在同一段视频的 43 张入选帧上，43 帧均检测到面部，43 帧的 mask 面积均小于 v5；第 001 帧预测下巴尖端在 640×480 图上的约 `(377, 299)`，与用户绿线所标位置接近。第 026、035 帧的预览也显示轮廓沿下颌收住，没有继续沿衣领走。面积减少仅说明裁剪发生，不能单独证明准确率；仍需对不同光线、转头、遮挡场景标注真值验证。

v3 使用额外的学习模型，是**离线参照实验**，不是原定的纯灰度边缘方案二，也不是已加入 C++ 插件的功能。`FaceLocator` 仍运行 v5。当前模型在 43 帧的检测调用平均约 8.8 ms，计时不包含完整视频或插件链路，不能直接推断摄像头帧率。

## 复现

v1/v2 需要 Python、Pillow 和 NumPy。脚本不覆盖已有迭代目录；复测时使用新名称：

```powershell
python tools/jaw_contour_probe.py --method free --iteration jaw-free-next
python tools/jaw_contour_probe.py --method parabola --iteration jaw-parabola-next
```

v3 另需 `mediapipe==0.10.35`。从[官方模型页面](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/index)下载 `face_landmarker.task`（本轮使用的 SHA-256：`64184E229B263107BC2B804C6625DB1341FF2BB731874B0BCC2FE6544E0BC9FF`），然后运行：

```powershell
python tools/jaw_landmark_probe.py --model C:\path\to\face_landmarker.task --iteration jaw-landmark-next
```

模型文件不在仓库中。v3 目录中的 `candidate/` 为绿色脸部外轮廓和黄色下巴点；`comparison/` 左侧是 v5，右侧是 v3；`mask-jaw/` 为 160×120 二值 mask；`results.csv` 记录位置、状态、面积和检测用时。若继续传统视觉路线，应先标注下巴边界，再把脸颊轮廓、下巴阴影与衣领边缘分别评分；强边缘本身不足以证明它属于下颌。
